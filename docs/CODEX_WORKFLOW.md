# Работа с Codex

Обязательные правила находятся в [AGENTS.md](../AGENTS.md), текущее состояние — в [STATUS.md](../STATUS.md).

## Одна задача в одном чате

Для новой самостоятельной задачи удобно открывать отдельный чат. Нужный контекст берётся из репозитория, а не из пересказа всей истории. Создание чатов и настройки интерфейса Codex выполняет пользователь; файлы проекта не могут сделать это автоматически.

Шаблон задачи:

> Направление: Python, ветка experimental.
> Задача: …
> Готово, когда: …
> Ограничения: …
> Изучи текущую реализацию, внеси изменения, проверь и покажи результат.
> Версию не меняй, ничего не публикуй.

Для C# указать `windows-native` и конкретный переносимый сценарий. При разборе ошибки полезны версия, ожидаемое и фактическое поведение, шаги воспроизведения и сообщение ошибки. Не прикладывать ключи и личные базы.

## Изменения и просмотр результата

1. Проверить ветку, рабочее дерево, статус проекта и затронутый код.
2. Зафиксировать критерии готовности. Рутинные технические решения выполнять самостоятельно в рамках задачи.
3. Реализовать законченный сценарий и проверить его на временных данных.
4. Для интерфейса показать реальный экран с тестовыми данными; макет обозначить явно. Убедиться, что изображение доступно пользователю.
5. Дать короткий отчёт: что изменилось, чем проверено, что осталось непроверенным. При необходимости обновить статус и changelog.

## Отдельный этап выпуска

Шаблон запроса после просмотра результата:

> Опубликуй подготовленные изменения в experimental. Базовую версию оставь прежней. Дождись CI и проверь архив с контрольной суммой. Stable и C# не затрагивай.

Push в `experimental` создаёт экспериментальный выпуск автоматически. Поэтому даже «просто запушить на проверку» запускает релизный процесс. До разрешения на выпуск использовать локальные проверки; отдельную проверочную ветку/PR можно создать, когда пользователь попросит проверить изменения в GitHub без выпуска.

Номер экспериментального запуска назначает GitHub. Неуспешные запуски оставляют пропуски. Для изменения базовой версии или переноса существующего тега требуется отдельное согласованное действие.

После разрешённого выпуска Codex проверяет CI и наличие ZIP + SHA256. Сообщение «отправлено в ветку» не заменяет подтверждения готового релиза.

## Диагностика

- `python tools/run_tests.py` и браузерные наборы выводят очищенные от известных форматов секретов ошибки в аннотации и summary GitHub.
- При падении браузерного сценария сохраняются снимок и ограниченный журнал консоли/ошибок страницы в `test-artifacts/`. Тесты используют временные данные и локальные фикстуры; не запускать этот сбор на личных аккаунтах.
- CI прикрепляет диагностические файлы при сбое. Не загружать папки данных приложения, cookies, профили браузера и произвольные дампы окружения.
- Для асинхронного интерфейса ждать конкретное состояние/элемент. Сетевая тишина может никогда не наступить из-за штатного опроса фоновых задач.
- Ошибка сохранения диагностики не должна скрывать первоначальное падение теста.
