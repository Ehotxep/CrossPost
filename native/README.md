# CrossPost Native — разработка 0.3.0-dev

Нативное приложение C# / WPF для Windows x64, без WebView2 и системного Python.
Это отдельный прототип, а не замена стабильному CrossPost.

Первый Windows-прототип 0.1.0 опубликован отдельно от Python-версий:
[релиз native-v0.1.0](https://github.com/Ehotxep/CrossPost/releases/tag/native-v0.1.0).

## Запуск

Инструкция ниже относится к ветке 0.3.0-dev. В опубликованном 0.1.0 доступно одно фото.

1. Распакуйте **весь архив** в отдельную папку.
2. Запустите **CrossPost.Native.exe**.
3. По умолчанию включён режим **ДЕМО**: сетевых запросов и публикаций нет.
4. Добавьте текст и до 10 изображений JPEG/PNG, выполните демо-отправку.
   Изображения можно переставлять кнопками «Выше»/«Ниже» и удалять по одному.
5. В истории выберите запись и попробуйте изменить её текст.

Сборка self-contained: .NET отдельно устанавливать не нужно.
Приложение пока не подписано сертификатом издателя; Windows может показать предупреждение.
Окно проверяется на Windows в CI; интерактивную проверку на пользовательском ПК ещё нужно выполнить.

## Реальная проверка Telegram

- Создайте приватный тестовый канал и добавьте своего бота администратором.
- В настройках укажите @имя_канала или числовой ID вида -100… и токен из @BotFather.
- Выключите демо-режим, сохраните настройки, нажмите «Проверить бота».
- Каждая реальная отправка и изменение требуют подтверждения с указанием действия.
- Bot API подключается по HTTPS; если он недоступен в вашей сети, MTProto в прототипе ещё нет.
- Токен вводится только в приложении и хранится с защитой Windows для текущего пользователя.
  Токен не входит в историю и базу черновиков.

В ветке разработки поддерживаются текст, одно фото или альбом из 2–10 изображений
до 10 МБ каждое. Порядок сохраняется в черновике. Подпись добавляется к первому фото. Текст свыше 1024 символов
отправляется отдельным сообщением перед фото/альбомом; редактирование меняет именно это сообщение.
Максимальная длина текста — 4096 символов. Текст обычный, введённый HTML не исполняется.

Если отправка прервана, результат может быть неизвестен: сначала проверьте канал.
Приложение не повторяет отправку автоматически. Если текст отправлен, а фото отклонено,
история сохраняет частичный результат и ID уже отправленного текста. Подтверждение текста
сохраняется на диск до запроса на загрузку альбома. История хранит все ID медиа.

## Очередь и расписание

- «В очередь» сохраняет отдельное задание на ближайшее выполнение; «Запланировать» — на выбранные дату и время.
- Дата и время вводятся в часовом поясе компьютера; в базе хранится UTC.
- Задание получает копии текста и изображений, исходный канал и идентичность бота. Правки черновика и смена канала в настройках его не меняют.
- Вкладка «Очередь»: пауза, перенос времени, отмена, переход к результату в истории, запуск и остановка фонового процесса.
- Окно можно закрыть: отдельный процесс `CrossPost.Native.exe --worker` продолжает выполнение без Python, службы Windows и прав администратора.
- После перезагрузки компьютера снова откройте CrossPost. Автозапуск Windows пока не настраивается.
- Если время пропущено более чем на 15 минут (например, компьютер был выключен), задание приостанавливается. Выберите новое время и продолжите вручную.
- Прерванные, частично отправленные и неподтверждённые публикации не повторяются автоматически. Проверьте канал.
- Включение деморежима приостанавливает реальные задания перед следующей отправкой. Смена бота тоже требует ручной проверки; отправка уже начатого запроса не отменяется переключением настройки.
- Файлы заданий сохраняются в `queue-media` внутри папки данных. Автоматического удаления этих копий пока нет.

## Данные

Отдельная папка %LOCALAPPDATA%/CrossPostNativePrototype:
- prototype.db — черновик, настройки без токена, история;
- telegram-token.dpapi — защищённый токен.

Python-база, настройки, сессии и очередь не читаются и не изменяются.
Файлы изображений используются по исходным путям; исходники не удаляются.
Для тестирования можно задать другую папку переменной CROSSPOST_NATIVE_DATA.

## Что ещё не реализовано

Замена медиа, видео, MTProto, импорт старой истории и сессий, теггер, другие площадки,
календарь и аналитика, автозапуск после входа в Windows, автоматические обновления.

## Сборка из исходников

Нужен .NET 10 SDK. Из папки `native` (здесь закреплена версия SDK):

    dotnet restore CrossPost.sln --locked-mode
    dotnet build CrossPost.sln -c Release --no-restore
    dotnet run --project tests/CrossPost.SmokeTests -c Release --no-build
    dotnet publish src/CrossPost.Desktop -c Release -r win-x64 --self-contained true -o artifacts/win-x64

CrossPost.SmokeTests — исполняемый набор проверок без реальных запросов к Telegram:
SQLite, демонстрационный режим, правильные методы Bot API, идентификаторы сообщений,
частичная отправка, неизвестный результат, отказ и редактирование.

Workflow **Windows native prototype** собирает ZIP и отдельно запускает настоящее окно WPF
в тестовой папке без реальной отправки. Это не полноценное ручное тестирование интерфейса.

## Ближайшие этапы

1. **Telegram — 0.2.0-dev:** альбомы, порядок изображений, сохранение всех ID и подтверждённого текста до следующего запроса. Проверить реальные отправки на тестовом канале вручную.
2. **Очередь и расписание — 0.3.0-dev:** отдельный фоновый процесс, снимки заданий, пауза/отмена, восстановление без повторной отправки. Проверяется отправка демо-альбома после закрытия окна и перезапуск процесса.
3. **Импорт и публикации:** чтение старой истории в отдельную базу, календарь, объединение, статистика.
4. **Другие API и медиа:** площадки по одной, видео и преобразования файлов.
5. **Теггер и браузерные площадки:** отдельные технические проверки перед переносом.

Автообновление будет отдельным этапом после разделения окна и Worker.

Команды управления Worker передаются по версионированному named pipe с доступом текущего пользователя. SQLite хранит задания; атомарное получение и эксклюзивный файловый дескриптор защищают от одновременного выполнения двумя процессами. Обычный запуск окна не меняет активную отправку Worker.
