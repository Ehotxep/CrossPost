# CrossPost Native — разработка 0.0.11-dev

Нативное приложение C# / WPF для Windows x64, без WebView2 и системного Python.
Это отдельный прототип, а не замена стабильному CrossPost.

Первый Windows-прототип 0.1.0 опубликован отдельно от Python-версий:
[релиз native-v0.1.0](https://github.com/Ehotxep/CrossPost/releases/tag/native-v0.1.0).

## Запуск

Инструкция ниже относится к ветке 0.0.11-dev. В опубликованном 0.1.0 доступно одно фото.

1. Распакуйте **весь архив** в отдельную папку.
2. Запустите **CrossPost.Native.exe**.
3. По умолчанию включён режим **ДЕМО**: сетевых запросов и публикаций нет.
4. Добавьте текст и JPEG/PNG, отметьте назначения и выполните демо-отправку.
   Для Telegram/Discord допускается до 10 изображений, для Bluesky — до четырёх.
   Изображения можно переставлять кнопками «Выше»/«Ниже» и удалять по одному.
5. В истории выберите запись и попробуйте изменить её текст.

Сборка self-contained: .NET отдельно устанавливать не нужно.
Приложение пока не подписано сертификатом издателя; Windows может показать предупреждение.
Окно проверяется на Windows в CI; интерактивную проверку на пользовательском ПК ещё нужно выполнить.

Нумерация прототипа изменена с `0.7.0-dev` на `0.0.7-dev`. Если уже установлена
`0.7.0-dev`, один раз замените файлы вручную полным архивом: прежний обновлятор
считает меньший номер понижением версии. Папка данных и схема базы не меняются.
Исторические нативные сборки до смены нумерации исключены из предложений обновления.

## Закрытие окна — 0.0.11-dev

Исправлено закрытие со второго нажатия: после сохранения черновика повторный Close
ставится в очередь диспетчера, чтобы он выполнялся после выхода из первого Closing.
Это работает и при синхронном завершении SQLite-операций. HTTP-клиент освобождается
только в Closed; при ошибке сохранения окно остаётся открытым и работоспособным.
Нажатия во время сохранения не запускают несколько операций закрытия.

Windows smoke закрывает окно обычным обработчиком после одного внешнего запроса,
с несохранёнными изменениями английского текста. Другой процесс затем проверяет
сохранённый черновик и выполнение ранее созданных заданий после закрытия окна.
При текущей ручной сетевой операции закрытие по-прежнему требует её завершения
или отмены; фоновый Worker продолжает работу независимо от окна.

## Интерфейс Python-версии в WPF — 0.0.10-dev

Оформление и компоновка взяты из `app/web`: палитра, Inter, верхняя панель, карточки
со скруглениями, второстепенные кнопки и отдельная панель публикации. Это нативные
WPF-контролы; HTML и WebView2 не используются. Inter встроен в приложение и поставляется
с исходной лицензией; установка шрифта на компьютер не требуется.

- Вверху: «Новый пост», «Публикации», «Статистика», «Настройки» и состояние фоновой очереди.
- В редакторе сначала карточка файлов с областью выбора/перетаскивания JPEG/PNG и галереей
  миниатюр, затем текст. Русский и английский варианты расположены рядом; на узком окне —
  друг под другом. Язык и отдельные тексты площадок продолжают работать.
- Справа — назначения с цветными значками и переключателями, отправка, очередь и расписание.
  Панель не прокручивается вместе с полями редактора. При небольшой высоте дополнительные
  параметры прокручиваются отдельно, основные кнопки остаются доступными.
- «Публикации» сохраняют постоянный календарь рядом со списком. Здесь находятся переходы
  в очередь и журнал правок; к очереди также ведёт индикатор в верхней панели.
- Журнал отображает список слева, сведения и редактор выбранной публикации справа.
- Настройки разбиты на страницы: общие, тексты площадок, Telegram, Discord и Bluesky.

Переключение экранов и страниц настроек не выполняет вход на площадки. Галерея использует
небольшие кэшированные миниатюры; исходные файлы не меняются. Ограничения C#-версии прежние:
видео/GIF, тренды и теггер ещё не перенесены; неработающие вкладки не показываются.

Windows smoke проверяет загрузку встроенного Inter, порядок карточек, независимость панели
от прокрутки, адаптацию языковых колонок и переключение страниц настроек. Снимки настоящего
окна, включая страницы подключений и галерею, находятся в UI-артефакте сборки.

## Оформление — 0.0.9-dev

Исправлено применение темы к MainWindow: фон, текст и шрифт явно задаются стилем окна,
а не неявным стилем базового Window. Поля, списки, заголовки и выпадающие меню используют
согласованные тёмные цвета, выбранные строки остаются читаемыми. Основная кнопка выделена
фиолетовым, второстепенные действия — нейтральные; текущий раздел отмечен в навигации.

Кнопки публикации и сохранения закреплены под формой и не прокручиваются вместе с ней.
На других экранах эта панель скрывается. Пустой предпросмотр изображения и пустой список
файлов не занимают место; действия с изображением отключены, пока оно не выбрано.

Windows smoke проверяет контраст основных надписей и полей, шаблон списка площадок,
видимость кнопки публикации при минимальном размере окна и сохраняет PNG настоящего WPF.
Снимки пустого редактора, разных размеров окна и разделов с тестовыми данными доступны
в отдельном артефакте `CrossPost-Native-UI-<версия>-win-x64`. Это клиентская область окна,
снятая WPF, без системной рамки Windows. Реальные настройки/публикации в снимки не входят.

## Кросспостинг — 0.0.7-dev

Отметьте назначения в блоке «Куда опубликовать». Переключатель «Предпросмотр» позволяет
проверить оформление и ограничения каждой площадки. У всех выбранных площадок проверяются
лимиты до сохранения заданий: превышение хотя бы на одной блокирует общий запуск без
обрезки текста и без частичной постановки в очередь. Для больших изображений Bluesky
сначала явно подготовьте копии. Отдельные тексты и языки доступны с 0.0.8-dev.

«Опубликовать в выбранные», «В очередь» и расписание используют один устойчивый механизм:
копии файлов и отдельное задание на каждое назначение сохраняются одной транзакцией.
Worker выполняет назначения последовательно. Результаты доступны в очереди и истории;
ошибка одного назначения не повторяет успешные отправки и не блокирует остальные.
Связанные публикации попадают в одну работу календаря, без отметки ручного объединения.
Выбор назначений запоминается. Перед реальным запуском показываются все выбранные назначения
и их деморежимы. Автоматического повтора частичных/неизвестных отправок нет.

## Обновления — 0.0.7-dev

В настройках есть текущая версия, каналы предварительных/стабильных **нативных** выпусков,
проверка при запуске, кнопка «Скачать и перезапустить» и установка из ZIP.
Поиск обращается только к GitHub. Python-релизы и выпуски без полного комплекта файлов
не предлагаются. Самостоятельная установка начинается только по кнопке.

Пакет скачивается по HTTPS из `Ehotxep/CrossPost`, проверяется SHA-256 и полный манифест
файлов, версия и архитектура. Контрольная сумма обеспечивает проверку целостности;
это не заменяет будущую подпись издателя. При ручном выборе ZIP используйте доверенный
нативный архив и одноимённый `.zip.sha256` рядом с ним.

Обновлятор дожидается завершения текущего задания, останавливает очередь, закрывает окно,
сохраняет прежнюю папку приложения и снимок базы, устанавливает файлы по прежнему пути.
Новая версия должна загрузить базу и окно и подтвердить готовность конкретного запуска.
До подтверждения пользовательские действия и запуск Worker заблокированы. Если запуск
не удался, возвращаются прежние файлы **и база**. Фоновая очередь возобновляется после
успешного обновления, если она работала перед установкой. Python-данные не затрагиваются.

Для версии до 0.7 необходима одна ручная распаковка полного архива в отдельную папку:
в прежних сборках обновлятора нет. Далее доступны обновления из настроек. Готовые ZIP из
Actions также можно устанавливать кнопкой «Установить из ZIP…» после извлечения внешнего
архива артефакта. Автоматическая проверка видит только опубликованные теги `native-v…`,
а не каждую сборку ветки; новый GitHub Release сейчас не создаётся.

Устанавливайте приложение в папку, доступную текущему пользователю; повышение прав не
запрашивается. Папка данных должна находиться отдельно. Папки через junction/symlink не
поддерживаются. Предыдущие файлы и журналы пока сохраняются без автоматической очистки.
Установщик, подпись издателя и восстановление после отключения питания посреди замены
остаются отдельными задачами. В SQLite используется схема 4; откат вручную на старые
бинарные файлы без восстановления соответствующей базы не поддерживается.

## Языки и отдельные тексты — 0.0.8-dev

В редакторе выберите общий режим **Русский / Оба / English**. Английский заголовок и
описание вводятся в раскрывающемся блоке English; автоматический перевод пока не подключён.
В режиме «Оба» сначала отправляются русский заголовок и описание, затем английские,
с разделением пустыми строками. Лимит считается по полному итоговому тексту.

В блоке выбранной площадки можно переопределить язык: «Как в общем тексте», «Русский»,
«Оба», «English». Это работает независимо от отдельных заголовков/описаний: например,
Telegram получает русский вариант, Discord — оба, Bluesky — английский.

Для собственных формулировок откройте **Настройки → Отдельные тексты площадок**,
отметьте нужные площадки и сохраните. Затем в редакторе выберите предпросмотр площадки
и включите «Использовать отдельный текст». При первом включении копируется общий текст;
дальнейшие изменения независимы. Отключение сохраняет введённый вариант, а отправка
снова использует общий текст с выбранным языком. Сохранённые пустые отдельные подписи
тоже сохраняются при переключениях; с изображением можно отправить пост без текста.

Предпросмотр показывает конкретный итог для выбранной площадки. Превышение лимита и
незаполненный необходимый язык видны до отправки. Если для English/«Оба» отсутствует
нужный текст, общий запуск блокируется до создания заданий: другой язык не подставляется.
Все варианты и языки автоматически сохраняются в черновике. Очередь получает уже
развёрнутый неизменяемый текст для каждого назначения; изменение языка/настроек после
планирования не меняет готовые задания. В истории сохраняется фактически отправленный текст.

Схема базы 5 и протокол Worker 5 защищают новые черновики от перезаписи старой программой.
При ручной замене архива сначала остановите очередь и закройте приложение; при установке
через обновлятор это выполняется автоматически. Старые русские черновики и задания
остаются русскими, перед миграцией создаётся резервная копия.

## Реальная проверка Telegram

- Создайте приватный тестовый канал и добавьте своего бота администратором.
- В настройках укажите @имя_канала или числовой ID вида -100… и токен из @BotFather.
- Выключите демо-режим, сохраните настройки, нажмите «Проверить бота».
- Каждая реальная отправка и изменение требуют подтверждения с указанием действия.
- Bot API подключается по HTTPS; если он недоступен в вашей сети, MTProto в прототипе ещё нет.
- Токен вводится только в приложении и хранится с защитой Windows для текущего пользователя.
  Токен не входит в историю и базу черновиков.

В ветке разработки поддерживаются текст, одно фото или альбом из 2–10 изображений
до 10 МБ каждое. Порядок сохраняется в черновике. Подпись добавляется к первому фото. Текст свыше 1024 символов
отправляется отдельным сообщением перед фото/альбомом; редактирование меняет именно это сообщение.
Максимальная длина текста — 4096 символов. Текст обычный, введённый HTML не исполняется.

Если отправка прервана, результат может быть неизвестен: сначала проверьте канал.
Приложение не повторяет отправку автоматически. Если текст отправлен, а фото отклонено,
история сохраняет частичный результат и ID уже отправленного текста. Подтверждение текста
сохраняется на диск до запроса на загрузку альбома. История хранит все ID медиа.

## Discord — 0.5.0-dev

В редакторе отметьте нужные назначения Telegram, Discord и Bluesky. Выбор площадки
в переключателе меняет предпросмотр; флажки определяют общий запуск.

1. В настройках Discord оставьте деморежим для проверки интерфейса без сети.
2. Для реальной отправки вставьте стандартную HTTPS-ссылку webhook текстового канала,
   выключите деморежим Discord и сохраните настройки. Эта проверка только читает сведения
   о webhook и не создаёт сообщения.
3. Вернитесь в редактор, выберите Discord и проверьте полный текст и вложения.
4. Отправьте сразу либо добавьте в очередь/расписание. Реальная отправка требует подтверждения.
5. Во вкладке «История • правки» можно изменить текст своего сообщения без удаления вложений.

Поддерживаются до 2000 символов и 10 JPEG/PNG (каждый до 20 MiB, суммарно до 24 MiB), спойлеры изображений и
отключение карточек ссылок. Текст не обрезается: превышение лимита нужно исправить до отправки.
Полный запрос ограничен 25 MiB; для JSON и заголовков оставлен запас. Лимиты сервера могут дополнительно ограничить загрузку; явный отказ сохраняется в истории.
Упоминания не вызывают уведомлений. GIF, видео, форумные каналы и ветки пока не подключены.

Webhook хранится в отдельном файле с Windows DPAPI. История и задания содержат ID webhook,
канала и сообщения, но не ссылку с токеном. Перед отправкой проверяется текущий канал webhook:
перенос webhook не перенаправляет сохранённое задание. Смена webhook приостанавливает старые
задания. При неопределённом результате или HTTP 429 автоматического повтора нет.

Деморежимы Telegram и Discord независимы. Выбор другой площадки не останавливает задания
первой. Настройки спойлера и карточек ссылок сохраняются в каждом задании.

При обновлении со старым работающим Worker сначала остановите очередь через вкладку
«Очередь» и запустите её заново. Версия 0.5 проверяет поддержку протокола перед добавлением
нового задания; старый процесс не получает задания Discord. Схема базы обновлена до версии 2
с резервной копией; прежние бинарные файлы не должны открывать обновлённую базу.

## Очередь и расписание

- «В очередь» сохраняет отдельное задание на ближайшее выполнение; «Запланировать» — на выбранные дату и время.
- Дата и время вводятся в часовом поясе компьютера; в базе хранится UTC.
- Задание получает копии текста и изображений, исходный канал и идентичность бота. Правки черновика и смена канала в настройках его не меняют.
- Вкладка «Очередь»: пауза, перенос времени, отмена, переход к результату в истории, запуск и остановка фонового процесса.
- Окно можно закрыть: отдельный процесс `CrossPost.Native.exe --worker` продолжает выполнение без Python, службы Windows и прав администратора.
- После перезагрузки компьютера снова откройте CrossPost. Автозапуск Windows пока не настраивается.
- Если время пропущено более чем на 15 минут (например, компьютер был выключен), задание приостанавливается. Выберите новое время и продолжите вручную.
- Прерванные, частично отправленные и неподтверждённые публикации не повторяются автоматически. Проверьте канал.
- Включение деморежима приостанавливает реальные задания перед следующей отправкой. Смена бота тоже требует ручной проверки; отправка уже начатого запроса не отменяется переключением настройки.
- Файлы заданий сохраняются в `queue-media` внутри папки данных. Автоматического удаления этих копий пока нет.

## Публикации, календарь и импорт — 0.4.0-dev

Вкладка «Публикации» содержит постоянный календарь и список работ. Для импорта выберите
`posts.db` Python-версии через кнопку «Импорт Python-базы…».

Импортёр открывает источник только для чтения и создаёт согласованный SQLite-снимок,
учитывающий WAL. Сначала создаётся резервная копия нативной базы; нормализованные записи
импортируются одной транзакцией. Отмена и ошибки откатывают изменения.

Переносятся публикации, посты каналов, внешние посты, замеры Telegram/ВК и ручные правила
объединения. Внешние ID сохраняются строками и сопоставляются вместе с площадкой и назначением.
Одинаковые ID из разных каналов остаются разными публикациями. Повторный импорт обновляет
данные без повторного добавления тех же внешних публикаций и замеров.

- Выберите несколько работ через Ctrl/Shift и нажмите «Объединить». Разные работы и площадки можно связать вручную без проверки сходства изображений.
- «Разъединить» возвращает отдельные публикации. Все исходные замеры сохраняются.
- Статистика берёт последнюю успешную публикацию для каждой пары площадка/назначение внутри работы, затем её последний замер. Максимальный счётчик из старых замеров не подставляется.
- Пустые счётчики показываются как «—», нулевые — как 0. Рядом с суммами указано покрытие: у скольких публикаций есть данные.
- Обычная публикация не помечается как объединённая. Показатель «Объединено вручную» относится только к явной связи нескольких записей.
- Статистика читает локальные данные: сайты, браузеры и фоновые запросы этот раздел не запускает.

Полный снимок исходной базы хранится в `imports/<номер>/source.db`, включая неизвестные поля
и таблицы. Старые задания и черновики остаются в этом архиве; они пока не переносятся в редактор
и рабочую очередь. Авторизация, токены, сессии, превью и медиа из Python-папки не импортируются.
Импортированные публикации доступны для просмотра; редактирование Telegram пока относится
к отправкам нативной версии во вкладке «История • правки».

Новые сетевые сборщики статистики, индекс успеха, прогнозы и графики роста пока не перенесены.

## Bluesky — 0.6.0-dev

В настройках Bluesky включён собственный деморежим. Для реальной отправки укажите handle
и **пароль приложения**, отключите деморежим и сохраните настройки. Проверка входа
не создаёт постов. Вход выполняется только по явной проверке/сохранению реальных настроек
или отправке; переключение вкладок, история и статистика не обращаются к Bluesky.
Пароль защищён Windows DPAPI, JWT существует только в памяти. В очереди закрепляется DID
аккаунта; смена аккаунта приостанавливает старые задания. Поддерживаются bsky.social и
его PDS `*.host.bsky.network`; собственные PDS пока не поддерживаются.

- До 300 графем и 3000 байт UTF-8, до четырёх JPEG/PNG по **2 000 000 байт**.
  Текст не обрезается. Ссылки, `[подпись](https://example.com)` и хештеги получают facets.
- ALT задаётся для выбранного изображения и перемещается вместе с ним.
- Рейтинг SFW / эротика / откровенное передаётся как отсутствие self-label / `nudity` / `porn`.
- «Подготовить копии» явно создаёт отдельные файлы: учитывает EXIF-поворот, уменьшает
  длинную сторону до 2048 без увеличения, удаляет метаданные. PNG сохраняет прозрачность;
  если нужен JPEG для соблюдения размера, прозрачность заменяется белым фоном.
  Оригиналы сохраняются. Перед отправкой проверьте подготовленный предпросмотр.
- Очередь копирует подготовленные файлы, ALT и рейтинг. Папка `prepared-media` сохраняется
  рядом с данными приложения, чтобы черновики и история не теряли изображения.
- URI будущего поста сохраняется до createRecord. При потерянном ответе результат
  остаётся неизвестным; автоматического повтора нет. Редактирование Bluesky недоступно,
  удаление с повторной публикацией автоматически не выполняется.

Схема базы обновляется до версии 3 с резервной копией. Перед заменой файлов остановите
старый Worker кнопкой управления очередью и закройте приложение. Возможности Worker
проверяются протоколом 3: старый процесс не принимает новые задания Bluesky.
Видео, GIF, разрешение упоминаний и сетевой сбор статистики Bluesky пока не реализованы.

Лимиты сверены с официальными lexicon:
[post](https://github.com/bluesky-social/bsky/blob/main/lexicons/app/bsky/feed/post.json),
[images](https://github.com/bluesky-social/bsky/blob/main/lexicons/app/bsky/embed/images.json).

## Данные

Отдельная папка %LOCALAPPDATA%/CrossPostNativePrototype:
- prototype.db — черновик, настройки без токена, история, очередь, работы и замеры;
- telegram-token.dpapi — защищённый токен;
- discord-webhook.dpapi — защищённая ссылка webhook Discord;
- bluesky-password.dpapi — защищённый пароль приложения Bluesky.

Python-база читается только при явном импорте. Настройки, сессии и рабочая Python-очередь не изменяются.
Файлы изображений используются по исходным путям; исходники не удаляются.
Для тестирования можно задать другую папку переменной CROSSPOST_NATIVE_DATA.

## Сборка из исходников

Нужен .NET 10 SDK. Из папки `native` (здесь закреплена версия SDK):

    dotnet restore CrossPost.sln --locked-mode
    dotnet build CrossPost.sln -c Release --no-restore
    dotnet run --project tests/CrossPost.SmokeTests -c Release --no-build
    dotnet publish src/CrossPost.Desktop -c Release -r win-x64 --self-contained true -o artifacts/win-x64

CrossPost.SmokeTests — исполняемый набор проверок без реальных запросов к Telegram:
SQLite, демонстрационный режим, правильные методы Bot API, идентификаторы сообщений,
частичная отправка, неизвестный результат, отказ и редактирование.

Workflow **Windows native prototype** собирает ZIP и отдельно запускает настоящее окно WPF
в тестовой папке без реальной отправки. Это не полноценное ручное тестирование интерфейса.

## Ближайшие этапы

1. **Telegram — 0.2.0-dev:** альбомы, порядок изображений, сохранение всех ID и подтверждённого текста до следующего запроса. Проверить реальные отправки на тестовом канале вручную.
2. **Очередь и расписание — 0.3.0-dev:** отдельный фоновый процесс, снимки заданий, пауза/отмена, восстановление без повторной отправки. Проверяется отправка демо-альбома после закрытия окна и перезапуск процесса.
3. **Импорт и публикации — 0.4.0-dev:** отдельная модель работ/публикаций/замеров, версионирование схемы и резервные копии, импорт истории, календарь и локальные показатели.
4. **Другие API и медиа:** 0.5.0-dev — Discord через webhook; 0.6.0-dev — Bluesky, ALT, рейтинги и подготовка изображений. Далее остальные официальные API и видео.
5. **Теггер и браузерные площадки:** отдельные технические проверки перед переносом.

Обновлятор реализован отдельным процессом; проверяется успешный запуск и возврат после неудачного запуска.

Команды управления Worker передаются по версионированному named pipe с доступом текущего пользователя. SQLite хранит задания; атомарное получение и эксклюзивный файловый дескриптор защищают от одновременного выполнения двумя процессами. Обычный запуск окна не меняет активную отправку Worker.

Ограничения Discord сверены с [Execute Webhook](https://docs.discord.com/developers/resources/webhook#execute-webhook), [Uploading Files](https://docs.discord.com/developers/reference#uploading-files) и [Create Message](https://docs.discord.com/developers/resources/message#create-message).
